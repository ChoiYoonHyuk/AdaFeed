# Three-bond path mass on ogbg-molhiv

Use all original 41,127 molecular graphs as one sparse block-diagonal adjacency. Load topology and element directly from the official raw release. Do not read bond classes, assay labels, splits or predictions. Mark noncarbon heavy atoms. Retain every carbon with no marked atom within distance two, including molecules with no marked atom. Before inspecting timing and numerical outcomes, fix two implementations of exactly the same seven-step contrast (in unscaled units). The GPU path starts from resident normalized sparse adjacency S and field p, forms sparse S² and S³, squares the nonzero entries of S³ and multiplies by p. The CPU path traverses the ball of radius three from each eligible root using a breadth-first queue, accumulating directed shortest-path probability before squaring at each distinct endpoint. Use reversibility to convert to the probability of visiting the marked endpoint at the midpoint of a six-step return. Select the same eligible roots. Require max absolute discrepancy below 1e-12 and matching signs among all extracted values.

After one warm-up, time five separately synchronized FP64 GPU extractions on the H100. Report the median, incremental Torch peak above the resident graph/field/indices, any other GPU context, intermediate nonzero counts and all-root audit. File I/O, eligibility and transfer of inputs to the device are outside the time. Arithmetic scales with the number of short paths and temporary power matrices may fill in on dense or high-degree graphs. This is a cost for the added scalar only. No speed comparison to a complete bank is part of the protocol.
